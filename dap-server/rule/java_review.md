# Java 代码评审规范

| 项 | 内容 |
|---|---|
| 文件 | `rule/java_review.md` |
| 用途 | `ada-review` 执行 Java 评审时注入给大模型的检查依据 |
| 说明 | 先提供最基础条目；团队可在本文件后续追加、修订 |

评审输出中的 `evidence` 应尽量引用本文件中的**规则编号**（如 `JAVA-NAMING-01`），并简述命中原因。

---

## 1. 命名（Naming）

| 编号 | 级别建议 | 规则 |
|---|---|---|
| JAVA-NAMING-01 | 低 | 类名使用大驼峰（PascalCase）；接口同样使用大驼峰，不以 `I` 前缀强制区分 |
| JAVA-NAMING-02 | 低 | 方法、变量使用小驼峰（camelCase）；常量使用全大写下划线（`UPPER_SNAKE_CASE`） |
| JAVA-NAMING-03 | 中 | 包名全小写，反向域名风格；禁止包名含大写或下划线 |
| JAVA-NAMING-04 | 中 | 布尔变量/方法避免歧义否定（少用 `isNotXXX`）；集合名用复数或带 `List`/`Map` 等语义后缀 |
| JAVA-NAMING-05 | 中 | 禁止无意义名称：`a`/`tmp`/`data1`/`obj` 等（极短循环变量 `i`/`j` 除外） |

---

## 2. 代码结构与可读性（Structure）

| 编号 | 级别建议 | 规则 |
|---|---|---|
| JAVA-STRUCT-01 | 中 | 单个方法不宜过长；建议超过约 80 行时拆分，职责单一 |
| JAVA-STRUCT-02 | 中 | 嵌套层级建议 ≤ 3；过深时用提前返回（guard clause）或提取方法 |
| JAVA-STRUCT-03 | 低 | 魔法数字/魔法字符串提取为有名常量或枚举 |
| JAVA-STRUCT-04 | 低 | 注释说明「为什么」，避免复述代码「做了什么」；过时注释必须删除或更新 |
| JAVA-STRUCT-05 | 中 | 禁止大段注释掉的死代码合入；应删除并由版本管理保留历史 |

---

## 3. 空值与集合（Null & Collection）

| 编号 | 级别建议 | 规则 |
|---|---|---|
| JAVA-NULL-01 | 高 | 对外 API / 公共方法明确空值约定；可能为 null 的返回需在调用侧判空或使用 `Optional`（团队统一一种风格） |
| JAVA-NULL-02 | 高 | 禁止对可能为 null 的对象直接解引用；链式调用前确认非空 |
| JAVA-NULL-03 | 中 | 返回集合时优先返回空集合而非 `null` |
| JAVA-NULL-04 | 中 | 遍历前确认集合非 null；增强 for 前勿假设调用方已判空 |
| JAVA-NULL-05 | 中 | 使用 `Objects.equals` / `Objects.requireNonNull` 等明确表达空值意图，避免隐式 NPE |

---

## 4. 异常与资源（Exception & Resource）

| 编号 | 级别建议 | 规则 |
|---|---|---|
| JAVA-EX-01 | 高 | 禁止空 `catch` 或仅打印后吞掉关键异常而不记录/上抛 |
| JAVA-EX-02 | 高 | 捕获异常后不得丢失原始 cause（保留 `throw new X(e)` / `initCause`） |
| JAVA-EX-03 | 中 | 不要用异常控制正常业务分支 |
| JAVA-EX-04 | 高 | IO / 连接 / 流等必须关闭；优先 try-with-resources |
| JAVA-EX-05 | 中 | 对外抛出的异常信息避免泄露敏感数据（密码、完整 SQL、内部路径等） |

---

## 5. 并发与线程安全（Concurrency）

| 编号 | 级别建议 | 规则 |
|---|---|---|
| JAVA-CONC-01 | 高 | 共享可变状态必须有同步策略（锁 / 并发集合 / 不可变）；禁止无保护的跨线程写 |
| JAVA-CONC-02 | 高 | 简单 `Date`/`SimpleDateFormat` 等非线程安全对象勿作成员在多线程间共享 |
| JAVA-CONC-03 | 中 | 捕获 `InterruptedException` 后应恢复中断状态或按约定处理，不可静默忽略 |
| JAVA-CONC-04 | 中 | 线程池须有界队列与拒绝策略；禁止无限制 `new Thread` 滥创 |

---

## 6. 集合、流与性能（Performance）

| 编号 | 级别建议 | 规则 |
|---|---|---|
| JAVA-PERF-01 | 高 | 禁止在循环内进行明显可外提的远程调用 / 数据库访问（N+1） |
| JAVA-PERF-02 | 中 | 已知大小时给集合指定初始容量；避免无谓的装箱拆箱热点 |
| JAVA-PERF-03 | 中 | Stream 中避免有副作用的复杂逻辑；过滤/映射保持可读 |
| JAVA-PERF-04 | 低 | 字符串大量拼接在循环中使用 `StringBuilder` |
| JAVA-PERF-05 | 中 | 大对象 / 字节数组避免不必要的多次拷贝 |

---

## 7. 安全（Security）

| 编号 | 级别建议 | 规则 |
|---|---|---|
| JAVA-SEC-01 | 高 | SQL / 命令 / 路径拼接禁止未校验的用户输入直接拼入（防注入、路径穿越） |
| JAVA-SEC-02 | 高 | 日志与响应中禁止输出密码、Token、密钥明文 |
| JAVA-SEC-03 | 高 | 反序列化不可信数据时须有白名单或避免 Java 原生危险反序列化 |
| JAVA-SEC-04 | 中 | 敏感配置不写死在源码；使用环境变量或配置中心 |
| JAVA-SEC-05 | 中 | 权限校验在服务端执行，不可仅依赖前端隐藏 |

---

## 8. API 与面向对象（API & OOP）

| 编号 | 级别建议 | 规则 |
|---|---|---|
| JAVA-API-01 | 中 | 类职责单一；上帝类（大量无关方法堆砌）应拆分 |
| JAVA-API-02 | 中 | 优先组合优于过深继承；继承用于「是一个」而非复用工具方法 |
| JAVA-API-03 | 低 | 覆写 `equals` 必须同时覆写 `hashCode` |
| JAVA-API-04 | 中 | 对外暴露的集合考虑不可变视图或拷贝，避免内部状态被外部修改 |
| JAVA-API-05 | 低 | 废弃 API 使用 `@Deprecated` 并注明替代方案 |

---

## 9. 日志与可观测（Logging）

| 编号 | 级别建议 | 规则 |
|---|---|---|
| JAVA-LOG-01 | 中 | 使用门面日志（SLF4J 等），禁止业务代码 `System.out.println` |
| JAVA-LOG-02 | 中 | 异常日志带上下文（业务主键、关键参数），使用 `log.error("...", e)` 保留堆栈 |
| JAVA-LOG-03 | 低 | 正确使用日志级别；热路径避免无意义 DEBUG 字符串拼接（用占位符） |
| JAVA-LOG-04 | 中 | 禁止在循环中打大量 INFO；高频日志降级或采样 |

---

## 10. 测试与变更卫生（Hygiene）

| 编号 | 级别建议 | 规则 |
|---|---|---|
| JAVA-HYG-01 | 中 | 关键业务逻辑变更应有对应用例或说明为何无法单测 |
| JAVA-HYG-02 | 低 | 新增代码不引入无用 import、无用私有方法 |
| JAVA-HYG-03 | 中 | 修改公共行为时评估调用方兼容性，避免静默改语义 |

---

## 使用说明（给评审引擎）

1. 以 **diff 变更为主**；问题须能在变更中定位，避免对未改动代码大规模扫雷。
2. `evidence` 格式建议：`[JAVA-XXX-0N] 规则摘要 — 具体命中说明`。
3. 级别以本表「级别建议」为默认；若同时违反业务知识，可上调严重度并注明。
4. 本文件未覆盖的问题，仍可按编码逻辑指出，但 `evidenceType` 标为 `LOGIC`，并写清推理过程。
