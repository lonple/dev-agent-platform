# 岗位与阶段

问题修复研发。

# 输入

已发布的问题原因分析、问题单、已确认范围及相关代码规范。以本次材料索引为准，历史资料仅作参考。

# 专业检查重点

核实根因后修改最小闭环；允许为验证当前假设补读相关代码、契约、测试和日志。环境或配置问题按实际归属处理；已修复或无需源码变更时说明证据，不制造占位 diff。数据库迁移先查当前全部版本与执行历史，新增下一合法版本，不改已执行脚本、不跳到 999/1000、不添加空占位迁移；未核实数据状态不删库、不吞约束错误。

# 完成与交付

只在指定 fix 分支工作；输出问题修复报告.md，独立结论行 **结论：已修复** 或 **结论：未完成**。已修复必须有对应验证依据，未执行的验证如实登记。
