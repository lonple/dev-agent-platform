# UI 设计规范

| 项 | 内容 |
|---|---|
| 文档类型 | UI-SPEC |
| 版本 | V1.0.0 |
| 状态 | 生效 |
| 适用范围 | 中后台 Web：管理台、业务操作台、配置台。不绑定某一产品、某一套业务对象 |
| 读者 | 生成 / 修订 / 评审 UI 的设计与研发；产品级规范只补充差异，不另写一套视觉 |
| 原则 | **全产品共用一套令牌、壳层和页面模式**。新产品沿用本规范扩展；业务枚举、菜单、字段写在产品规范里，不写进本文件 |

本规范规定视觉、布局、组件语义和交互套路。技术栈、接口字段、权限码、页面清单由产品架构与产品 UI 规范给出。默认组件语义可落到 Element Plus 一类中后台组件库，见 §9；HTML 原型与前端实现使用同一套令牌，禁止单页另起视觉语言。

---

## 1. 目标与范围

### 1.1 目标

- 统一颜色、间距、布局、组件用法和文案语气，避免各页各自为政
- 列表、表单、详情、操作台有固定结构，新页面照模式落地，不临时发明布局
- 权限、状态、空态、加载、错误有固定套路，减少临场发挥

### 1.2 范围

| 包含 | 不包含 |
|---|---|
| 需登录的中后台 Web：壳层、登录、列表、表单、详情、对话框、操作台 | 营销落地页、品牌官网、数据大屏、打印模板 |
| 设计令牌、组件语义、交互与文案 | 某一产品的菜单树、字段、枚举文案、接口 |
| 线框级页面模式，供原型和实现共用 | 高保真视觉稿、插画、动效品牌片 |

移动端不在本版保证范围内。若产品需要移动端或读者门户一类独立端，另立端规范，并声明与本规范的差异。

### 1.3 产品规范与本规范的分工

| 写在本规范 | 写在产品 UI 规范 |
|---|---|
| 色板、字号、间距、圆角、壳层 | 产品名称、Logo 文案 |
| 列表 / 表单 / 详情 / 操作台的结构 | 菜单、路由、页面清单 |
| 按钮层级、确认、反馈、空态 | 业务状态枚举到语义色的映射 |
| 权限、分页、文案的通用规则 | 字段、校验、与接口对齐的交互 |

产品规范不得改主色语义、不得改危险操作的确认方式、不得在单页使用未登记的色值。需要例外时，在产品规范中单列「例外」，并说明原因和范围。

## 2. 设计令牌（Design Tokens）

新增页面引用下列语义，禁止在页面里硬编码散落色值和间距。实现上先落成 CSS 变量，再在组件里引用。

### 2.1 色板

| Token | 色值 | 用途 |
|---|---|---|
| `--color-primary` | `#409EFF` | 主操作、当前导航、链接型主操作 |
| `--color-success` | `#67C23A` | 成功、完成、正向终态 |
| `--color-warning` | `#E6A23C` | 警告、进行中、需关注但未失败 |
| `--color-danger` | `#F56C6C` | 删除、冻结、失败、不可逆操作 |
| `--color-info` | `#909399` | 次要信息、中性或弱状态 |
| `--color-sidebar-bg` | `#304156` | 侧栏背景 |
| `--color-sidebar-text` | `#bfcbd9` | 侧栏默认文字 |
| `--color-sidebar-border` | `#3d4a5a` | 侧栏内分割线 |
| `--color-text-primary` | `#303133` | 标题、主文案 |
| `--color-text-regular` | `#606266` | 正文、顶栏用户名 |
| `--color-text-secondary` | `#909399` | 辅助说明、空态文案、占位 |
| `--color-border` | `#DCDFE6` | 分割线、表格与输入边框 |
| `--color-bg-page` | `#f5f7fa` | 页面底、登录页底 |
| `--color-bg-card` | `#FFFFFF` | 卡片、对话框、顶栏 |

语义色只表达语义：成功、警告、危险、信息。业务状态选择其中一档，不另造近义色。

**禁止**：紫色渐变主题、大面积霓虹发光、用主色铺满页面背景、同一语义在不同页面用不同颜色。

### 2.2 字号与字重

| 级别 | 字号 | 字重 | 场景 |
|---|---|---|---|
| 页面 / 卡片标题 | 16–18px | 600 | 壳层产品名、卡片标题 |
| 登录大标题 | 20–24px | 600 | 登录页产品名 |
| 正文 | 14px | 400 | 表单、表格、按钮 |
| 辅助 | 12–13px | 400 | 空态说明、字段提示、次要元信息 |

字体栈跟随系统界面字体。中后台不引入展示型字体。同一级别全产品只用一档，不在单页加大标题制造强调。

### 2.3 间距、尺寸与圆角

| Token | 值 | 场景 |
|---|---|---|
| 区块间距 | 20px | 卡片内筛选区与表格、表格与分页 |
| 顶栏高度 | 60px | 与侧栏 Logo 区对齐 |
| 侧栏宽度 | 200px | 固定；折叠为后续增强，本版不作为默认 |
| 表单 label 宽 | 100px | 对话框与单列表单统一；标签普遍较长时可提到 120px，全产品只保留一档 |
| 对话框宽度 | 480px / 600px / 800px | 简单表单 480；标准编辑 600；双列或宽表格 800。确认框用消息确认，不用对话框 |
| 登录卡 | 宽 400px，内边距 20px | 居中单卡 |
| 圆角 | 4px | 按钮、输入、卡片、对话框。不使用大圆角或胶囊卡片 |

间距只用 4 的倍数：4、8、12、16、20、24。页面不混用随意像素。

### 2.4 阴影与层级

| 层级 | 用法 |
|---|---|
| 页面底 | 无阴影，仅背景色区分 |
| 卡片 | 组件库默认轻阴影 |
| 对话框 / 确认框 | 组件库默认遮罩与阴影，遮罩阻断底层操作 |
| 顶栏 | 白底 + 底部分割线，不另加厚阴影 |

同一屏幕只存在一个模态层。不叠两层对话框。

## 3. 布局模式

业务页从下列模式里选一种。模式不够用时先补产品规范，再谈新模式。

### 3.1 应用壳

```
┌──────────┬────────────────────────────┐
│  Logo    │  Header（右：姓名 + 退出）   │
│  侧栏菜单 │────────────────────────────│
│  200px   │  Main：业务页（卡片为主）     │
│  深色    │                            │
└──────────┴────────────────────────────┘
```

- 需登录的业务页都放在该壳层内。登录、找回密码等公开页不进壳层
- 侧栏：背景 `--color-sidebar-bg`，默认字 `--color-sidebar-text`，当前项 `--color-primary`
- 顶栏白底，底部分割线；右侧为当前用户名称和「退出」
- 内容区以卡片承载。一页一件主任务时用一张卡片；任务自然分成多块时用多张卡片。不用无卡片的裸表格贴在灰底上
- Logo 区只放产品名，不放口号

### 3.2 登录页

- 全屏居中，背景 `--color-bg-page`
- 单卡片，标题居中，主按钮通栏
- 账号、密码必填。密码可切换明文。字段带前缀图标
- 成功后进入该用户有权限的首页；失败展示服务端返回的原因

### 3.3 标准列表页

自上而下固定顺序：

1. **卡片头**：左标题，右主操作（如「新增」）。同一层级只有一个主按钮
2. **筛选区**（需要时）：行内表单。查询为主按钮，重置为默认按钮，成对出现
3. **表格**：有边框、斑马纹。操作列固定在右侧，行内操作使用文字按钮
4. **分页**：右对齐。包含总条数、每页条数、上一页、页码、下一页、跳转。每页条数 `10 / 20 / 50 / 100`，默认 20
5. **新增与编辑**：复用同一个对话框，标题随创建或编辑切换

无筛选的短列表可以省略筛选区，其余顺序不变。

### 3.4 详情页

- 卡片头为对象名称，右侧放该对象的主操作
- 主体用描述列表，两列或三列对齐，标签宽与表单一致
- 关联子资源用分割线或次级卡片分块，子表遵循 §3.3 的表格规则
- 只读字段不放进可编辑输入框

### 3.5 表单

- 字段少、依赖列表上下文：用对话框，不单独开路由
- 字段多、有分步或要独立链接：用整页表单，卡片内分组，底部操作栏固定「取消 + 确定」
- 分组标题放在组的左侧，组与组之间用分割线，不使用多套卡片标题样式

### 3.6 操作台

适用于「选对象 → 执行动作 → 看结果」，而不是维护主数据。

- 一张卡片内按任务分块，块标题靠左
- 每块是行内表单加一枚语义明确的主按钮
- 动作颜色按结果语义，而不是按业务名词：完成或正向动作用成功色，需关注用警告色，不可逆用危险色，普通提交用主色
- 需要同时查记录时：上方操作、下方列表，或用页签分开。页签不超过两个主任务

## 4. 组件用法

### 4.1 按钮

| 场景 | 样式 | 说明 |
|---|---|---|
| 页头主操作 | 主按钮 | 同一卡片头、同一表单底栏只放一个 |
| 查询 | 主按钮 | 与重置成对 |
| 重置、取消、返回 | 默认按钮 | 取消位于确定左侧 |
| 行内编辑、查看 | 文字按钮，主色 | — |
| 行内删除、冻结、作废 | 文字按钮，危险色 | 必须二次确认 |
| 正向完成类动作 | 成功色按钮 | 如提交完成、确认归还 |
| 需关注的主动作 | 警告色按钮 | 页面上同时只强调一个此类动作 |
| 退出 | 顶栏文字按钮 | 不使用危险色 |

提交、保存、删除等会发请求的按钮进入加载态，结束前不可再次点击。

### 4.2 表格

- 有边框、斑马纹
- 状态列用标签，不用纯文字加散落色值
- 数字、金额、数量列居中或右对齐，同一产品只选一种并保持
- 文本列左对齐。过长文本单行省略，悬停看全文
- 操作列宽：一个操作约 80–100px，两个约 150px，三个及以上改为「更多」
- 空数据使用组件库空态，文案见 §5.3
- 列顺序：标识、名称、关键业务字段、状态、时间、操作。操作列在最右并固定

### 4.3 表单

- 必填由校验规则提示在字段下方，不靠提交后再弹一条「请填写完整信息」代替
- 占位符统一为「请输入…」「请选择…」，不把占位符当作标签
- 对话框内的下拉、日期、数字输入与字段同宽
- 数量用数字输入，并设置最小、最大和步长
- 密码可切换明文。编辑已有账号时，密码单独走「重置密码」，不在编辑表单里回显
- 一个字段只有一个错误文案，指出怎么改

### 4.4 对话框与确认

| 类型 | 形式 | 约定 |
|---|---|---|
| 新增 / 编辑 | 对话框 | 底部：取消 + 确定。确定为主按钮并带加载态 |
| 危险或不可逆 | 确认框 | 标题「提示」。正文写明对象名称和后果 |
| 状态变更（冻结、停用、作废） | 确认框 | 先说明后果，再请求接口 |
| 离开未保存表单 | 确认框 | 说明未保存内容将丢失 |

确认框的确定按钮与动作同色：删除用危险色，普通确认用主色。正文使用对象的业务名称，避免只写「确定删除吗」而不指明删的是哪一条。

### 4.5 反馈

| 结果 | 形式 | 文案 |
|---|---|---|
| 成功 | 成功提示，自动消失 | 「保存成功」「新增成功」「更新成功」「删除成功」 |
| 失败 | 错误提示 | 优先展示服务端给出的原因，否则「操作失败」或「加载失败」 |
| 字段校验 | 字段下方错误 | 不升格成全局错误提示 |
| 未选择就操作 | 警告提示 | 「请先选择一条记录」 |
| 未登录或登录失效 | 清除会话并回到登录页 | 不在业务页堆叠多个错误 |

成功和失败使用不同的提示类型。不用浏览器原生 `alert`。操作结果不写进页面标题。

### 4.6 状态标签

标签颜色只有四档，全产品共用：

| 语义 | 颜色 | 适用 |
|---|---|---|
| 正向、可用、已完成 | success | 启用、正常、已通过、已完成 |
| 进行中、待处理 | warning | 待审核、进行中、即将到期 |
| 失败、停用、不可逆 | danger | 已拒绝、已冻结、已关闭、失败 |
| 中性、完结但不强调 | info | 草稿、已归档、已注销、未知 |

产品规范用一张表把业务枚举映射到上表，包含：存储值、界面文案、标签语义。表格、详情、筛选项使用同一文案。界面上不直接显示未映射的英文枚举或内部码。

未知枚举显示「未知」，用 info，并保留原始值供排查，不把它显示成成功或失败。

## 5. 交互与内容

### 5.1 权限

- 无菜单权限：不渲染该菜单。一组子项都不可见时，父级一并隐藏
- 无操作权限：不渲染对应按钮。后端拒绝仍要提示，前端隐藏不是唯一防线
- 直接打开无权限地址：回到该用户第一个有权限的页面，并提示「您没有此操作权限」
- 只读权限：页面可进，编辑、删除、提交不出现

权限码的具体取值写在产品规范，本规范只规定可见性规则。

### 5.2 查询与分页

- 点击查询，或修改每页条数：页码回到第 1 页
- 空的筛选项不传给接口
- 新增成功：回到第 1 页并刷新。编辑成功：留在当前页并刷新
- 筛选条件在翻页时保持。重置清空条件并回到第 1 页
- 删除当前页最后一条后，若当前页已空且不是第一页，则请求上一页

### 5.3 空态、加载与错误

| 状态 | 表现 |
|---|---|
| 表格或区块加载 | 该区域加载态，不全屏遮罩，除非整页依赖这一份数据 |
| 无数据 | 「暂无数据」。提供主操作时，空态可带一个主按钮 |
| 有筛选但无结果 | 「无符合条件的数据，请调整筛选」 |
| 加载失败 | 错误提示。保留上一次成功的数据；没有上一次数据时显示空表。不白屏 |
| 整页无权限 | 单独的结果说明，不连续弹出多条错误 |
| 提交失败 | 对话框保持打开，表单内容保留，字段错误写回字段 |

### 5.4 文案

- 界面文案使用简体中文
- 按钮用动宾或双字：查询、重置、新增、编辑、删除、保存、确定、取消、返回
- 删除确认：「确定要删除该{对象}吗？」对象用业务名称，必要时带出关键识别字段
- 同一动作全产品只用一个词。已使用「新增」就不再在别的页面写「新建」「添加」
- 中后台不用 emoji 作装饰

## 6. 信息架构

- 侧栏按使用频率分组，一组不超过 7 项。超过时分组，而不是继续堆平铺
- 当前页在侧栏中有且仅有一个选中项
- 菜单、页头标题、浏览器标题使用同一个业务名称
- 图标使用同一图标集，一个菜单一个图标，不混用多种风格
- 图标只辅助识别，不单独承担含义；其旁始终有文字

产品规范列出菜单顺序、名称、图标名。本规范不规定具体业务菜单。

## 7. 响应式与浏览器

| 项 | 约定 |
|---|---|
| 目标 | 桌面中后台，宽度不小于 1280px 时布局完整 |
| 窄于 1280px | 表格允许横向滚动。本版不默认做侧栏折叠 |
| 浏览器 | Chrome、Edge 近两个大版本 |
| 移动端 | 不保证。登录页允许在窄屏下仍可完成登录 |

## 8. 工程落地

### 8.1 样式

令牌集中在一处，例如：

```
src/styles/tokens.css    色板、字号、间距
src/styles/layout.css    壳层、页头、筛选区、分页
```

页面样式保持局部。多页重复的页头、筛选区、分页条抽成公共类或布局组件，不在每个页面复制一套间距。

### 8.2 建议沉淀的通用件

| 通用件 | 职责 |
|---|---|
| 页面卡片 | 左标题、右操作 |
| 筛选条 | 筛选项插槽，内含查询与重置 |
| 状态标签 | 入参为枚举值，输出文案和语义色 |
| 远程选择器 | 关键词搜索，展示「名称（编号）」，绑定标识 |

通用件不含业务文案。业务字段、枚举字典由产品注入。

### 8.3 版本

- 更换主色、壳层结构或页面模式：升本规范版本
- 只增加产品页面、不改令牌：改产品 UI 规范，本规范仅在被证明缺模式时修订

## 9. 默认实现对照

以下对照方便落到 Element Plus。换组件库时保持语义，不保持类名。

| 规范 | 默认实现 |
|---|---|
| 主按钮 / 成功 / 警告 / 危险 | `type` 为 `primary` / `success` / `warning` / `danger` |
| 行内操作 | `link` 按钮 |
| 表格 | `border` 与 `stripe` |
| 状态 | `el-tag` 的 `success` / `warning` / `danger` / `info` |
| 标准对话框 | 宽 600px；底部取消 + 确定 |
| 危险确认 | `ElMessageBox.confirm`，`type=warning`，确定按钮危险色 |
| 全局反馈 | `ElMessage`，成功、警告、错误分开 |
| 加载 | 表格或表单容器上的加载态 |
| 图标 | 同一图标包，菜单与输入前缀都从该包选取 |

中文界面使用组件库的中文语言包。

## 10. 检查清单

评审原型或页面时逐项核对：

- [ ] 页面属于壳层、登录、列表、详情、表单、操作台之一
- [ ] 色值来自 §2.1，状态只用四档语义色
- [ ] 列表具备标题区、按需筛选、有边框斑马纹表格、右对齐分页
- [ ] 同一区域只有一个主按钮
- [ ] 删除、冻结、作废等不可逆操作有确认框，且点明对象
- [ ] 成功与失败的提示类型不同，文案为简体中文
- [ ] 枚举有中文文案和标签，不直接显示内部码
- [ ] 无权限的菜单和按钮不渲染
- [ ] 标准对话框标签宽、宽度符合 §2.3
- [ ] 查询把页码重置为 1；提交按钮有加载态
- [ ] 空数据、筛选无结果、加载失败三种状态文案不同
